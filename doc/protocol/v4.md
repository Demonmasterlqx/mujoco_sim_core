# Protocol V4

Protocol V4 is the repository's only wire contract. Protobuf package names use
`mujoco_sim.v4`, topic paths use `mujoco_sim/v4`, data framing reports version
2.0, and every dense frame starts with magic `MJDATA4\0`. There is no version
negotiation or compatibility endpoint.

High-frequency kinds are fixed: Controller State is 1, Controller Command is
2, and Observation is 3. Flags must be zero. State and Observation use an
80-byte little-endian header containing session, epoch, completed-step tick,
layout fingerprint, frame sequence, and simulation time. Command uses a
64-byte header containing only session, epoch, command layout fingerprint, and
Command sequence. Payloads are dense little-endian doubles and the complete
frame limit is 4 MiB.

## Dense frame layout

The first 24 bytes are common to every dense frame:

| Offset | Size | Field |
| ---: | ---: | --- |
| 0 | 8 | magic `MJDATA4\0` |
| 8 | 2 | framing major, `2` |
| 10 | 2 | framing minor, `0` |
| 12 | 1 | kind: State `1`, Command `2`, Observation `3` |
| 13 | 1 | flags, always `0` |
| 14 | 2 | kind-specific header size |
| 16 | 4 | complete frame size in bytes |
| 20 | 4 | scalar count |

State and Observation then use the same 80-byte header:

| Offset | Size | Field |
| ---: | ---: | --- |
| 24 | 8 | session ID |
| 32 | 8 | model epoch |
| 40 | 8 | completed-step tick ID |
| 48 | 8 | layout fingerprint, low word |
| 56 | 8 | layout fingerprint, high word |
| 64 | 8 | frame sequence |
| 72 | 8 | simulation time as an IEEE-754 `double` bit pattern |

Command uses a shorter 64-byte header:

| Offset | Size | Field |
| ---: | ---: | --- |
| 24 | 8 | session ID |
| 32 | 8 | model epoch |
| 40 | 8 | command-layout fingerprint, low word |
| 48 | 8 | command-layout fingerprint, high word |
| 56 | 8 | Command sequence |

All integers, fingerprint words, floating-point bit patterns, and payload
scalars are little-endian. Every sequence is nonzero. Parsers require the
header size implied by the kind, the exact encoded frame size, and
`scalar_count * 8` payload bytes; V3 magic/framing and unknown flags or kinds
are rejected.

Registration returns the complete resource layout and Controller runtime
policy. Layout fingerprints use the Protocol canonical length-prefixed encoding
and FNV-1a 128. A Controller Command sequence starts at 1 and is strictly
increasing within a session. Command has no source-State, tick, or simulation
time field.

Control/status messages use Protocol V4 Protobuf. Controllers send Commands and
optional `ControllerFault`, but no heartbeat. Observers retain heartbeat and
delivery negotiation. `ControllerFault` contains session, epoch, code, and
message. Adapter state values are fixed as `UNSPECIFIED=0`, `PROVISIONAL=1`,
`ACTIVE_NO_COMMAND=2`, `ONLINE=3`, `OFFLINE=4`, `ERROR=5`, and
`UNREGISTERED=6`.

## Endpoints and lifecycle

For Server name `<server>` and Adapter ID `<adapter>`, the registry service is
`mujoco_sim.v4.<server>.registry`. Runtime topics are:

| Traffic | Topic |
| --- | --- |
| Controller State | `mujoco_sim/v4/<server>/controller_state/<adapter>` |
| Controller Command | `mujoco_sim/v4/<server>/controller_command` |
| Observation | `mujoco_sim/v4/<server>/observation/<adapter>` |
| Observer heartbeat | `mujoco_sim/v4/<server>/session_heartbeat` |
| Controller fault | `mujoco_sim/v4/<server>/controller_fault` |
| Server status | `mujoco_sim/v4/<server>/status` |
| Sensor stream | `mujoco_sim/v4/<server>/sensor/<stream>` |

Sensor topics do not use the dense `MJDATA4` codec. They carry a 24-byte
`MJSTREAM` 1.0 prefix, a serialized V4 `StreamFrameHeader`, and the raw image or
point payload. The serialized header limit is 1 MiB and the payload limit is
512 MiB.

Registration creates a `PROVISIONAL` session and returns its immutable layout.
Controller activation enters `ACTIVE_NO_COMMAND`; the first valid Command
enters `ONLINE`, a command deadline enters `OFFLINE`, and a later valid Command
returns it to `ONLINE`. A valid Fault enters terminal `ERROR`. Stale,
duplicate, malformed, non-finite, and out-of-range Commands are rejected
without refreshing liveness or changing the session to `ERROR`.

See [Controller lifecycle](../architecture/controller_lifecycle.md) and the
[asynchronous sequence](../architecture/async_controller_sequence.md) for the
runtime boundary rules.
